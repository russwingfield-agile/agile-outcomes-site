    How the data was linked

    Where to focus

    Findings are worked out from the figures above.

    How to read these numbers

    • DORA-style, not DORA-exact. The four DORA measures are defined for services that deploy to production. Open-source projects publish releases instead, so a release (a Jira version marked as released) stands in for a deployment.
    • Lead time runs from the first pull request for a ticket being opened to the release date of the first release that contains it. It splits cleanly into review time and waiting time, which is where the useful finding usually is.
    • Change failure means a Blocker or Critical bug that names a release as affected, raised within 30 days of it. It depends on people setting "affects version", so a clean record can partly be a quiet one.
    • Time to restore runs from such a bug being raised to the release that fixed it, not to the fix being merged.
